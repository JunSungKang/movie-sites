# Docker 배포

[English](../docker.md) · [문서 목록](../../README.ko.md#문서)

Linux 컨테이너 엔진을 사용합니다. 다단계 Dockerfile은 JDK 25와 Gradle Wrapper로 빌드한 JAR를 Java 런타임·Ubuntu FFmpeg 패키지와 실행합니다. 별도 프론트엔드 서버는 없습니다. 현재 저장소는 소스 빌드 Dockerfile을 제공하며 검증하지 않은 레지스트리 이미지를 안내하지 않습니다.

## 첫 실행

전체 명령은 [README](../../README.ko.md#docker)에 있습니다. 호스트 디렉토리를 먼저 준비하고 원본은 `/media`에 읽기 전용, 생성 데이터는 `/data`에 쓰기 가능하게 마운트합니다. 예시 환경변수도 컨테이너 경로를 사용합니다.

기본 사용자는 UID/GID `10001:10001`입니다. 데이터 경로에 해당 사용자의 쓰기 권한을 부여하거나 Linux/macOS의 사용자 소유 경로에는 `--user "$(id -u):$(id -g)"`를 사용합니다. 전체 쓰기 허용으로 해결하지 마세요. Docker Desktop에서는 경로 공유도 확인해야 합니다.

Windows는 Linux 컨테이너를 사용하고 `source=C:\Media,target=/media,readonly` 같은 절대 공유 경로를 지정합니다. `$(pwd)`·`id`는 PowerShell 명령이 아니므로 마운트 경로를 바꾸고 POSIX 사용자 표현식을 생략합니다.

## 상시 실행

첫 실행의 포그라운드 `--rm` 대신 `-d --restart unless-stopped`를 사용할 수 있습니다. 선택적 제한 예시는 `--read-only --memory=2g --cpus=2 --pids-limit=128`이며 실제 부하로 확인해야 합니다. Java 임시 파일은 쓰기 가능한 `/data` 아래에 저장합니다. 데이터 루트는 독점 잠금하므로 인스턴스별로 분리합니다.

설정·버전 변경은 컨테이너를 정지하고 교체합니다. 외부 마운트를 재사용하면 원본과 생성 데이터를 유지할 수 있습니다. 검증 전까지 이전 이미지·실행 설정을 복구용으로 남기세요. 같은 데이터 루트에 구·신 인스턴스를 동시에 실행하지 마세요.

## NAS·네트워크 드라이브

먼저 호스트에 마운트하고 정상 연결을 확인한 뒤 원본 경로로 bind합니다. 생성 데이터는 적절한 쓰기 가능 저장소에 둡니다. 실제 파일시스템의 Java 보안 디렉토리 작업 지원을 확인하고 목록·파일·부분 범위 요청을 시험하세요. 상태 API는 NAS 전체를 검사하지 않습니다.

전체 트리 검색·재귀 감시는 없습니다. OS 파일 호출이 멈추면 애플리케이션 타임아웃 이후에도 남을 수 있으므로 저장소 장애·자원 동작을 환경별로 확인해야 합니다.

## 접속과 진단

README는 호스트 내부 `127.0.0.1:8080`만 공개합니다. 다른 기기에 서비스하려면 공개 주소·방화벽·접근 제어·TLS를 구성하세요. 로그인 기능은 없으며 접속 가능한 방문자는 지원 영상을 볼 수 있습니다. `PORT` 변경 시 내부 포트와 공개 매핑도 맞춰야 합니다.

`/api/health`, 컨테이너 health와 시작 로그를 확인하세요. 정상 상태는 애플리케이션 응답을 뜻하며 모든 파일·NAS 연결 보증은 아닙니다. [문제 해결](troubleshooting.md)과 [설정](configuration.md)을 참고하세요.
