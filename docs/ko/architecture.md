# 아키텍처

[English](../architecture.md) · [문서 목록](../../README.ko.md#문서)

JDK 25·Spring Boot 4.1.2 애플리케이션 하나가 정적 HTML/CSS/ES 모듈·JSON API·영상 스트림을 제공합니다. Gradle은 실행 가능한 JAR 하나를 만듭니다. 외부 파일시스템이 원본 목록의 기준이며 원본·생성 데이터 루트는 분리합니다.

## 탐색과 상태

열어 본 폴더의 바로 아래만 열거합니다. 화면은 아래 길이순 조회를 사용하며 기존 스트리밍 API도 유지합니다. DB·시작 시 전체 검색·전역 색인·하위 개수 계산·재귀 감시는 없습니다. 기본 페이지는 지원 항목 최대 48개입니다. 기존 파일시스템 순서 API는 호출당 최대 1000개를 검사하며, 길이순 조회는 정확한 첫 페이지를 위해 현재 폴더 전체 항목을 확인합니다. 기존 파일시스템 순서 API는 정렬된 스냅샷이 아니므로 빈 페이지에도 다음 커서가 있을 수 있습니다.

기존 파일시스템 순서 API의 디렉토리 세션은 최대 8개이며 유휴 시 정리합니다. 커서는 경로·순서에 묶이며 재사용·만료·불일치는 오류입니다. 읽기 작업자 2개와 제한된 대기열을 사용하고 탐색 API는 8초 후 시간 초과할 수 있습니다. 멈춘 OS 파일 호출의 즉시 취소를 보증하지는 않습니다.

완성 스냅샷은 설정된 60~180초 동안 재사용하고 같은 폴더의 준비 요청도 합칩니다. `refresh=true`는 새 조회를 시작합니다. HTTP·브라우저에는 남은 유효 시간만 전달해 캐시를 겹쳐도 전체 TTL을 다시 시작하지 않습니다.

탭별 메모리 LRU는 응답 20개·항목 2000개·직렬화 크기 약 10 MiB로 제한합니다. TTL 기본 120초는 최초 조회 기준이며 적중으로 연장되거나 만료 시 배경 조회하지 않습니다. 제한된 sessionStorage로 만료되지 않은 페이지만 복원하며 루트·서버 인스턴스가 바뀌면 버립니다. 새로고침은 브라우저와 서버 목록 캐시를 우회합니다. 최근 페이지 이동 기록은 20개입니다. 이동된 파일을 전체 검색하지 않습니다.

## 저장소 경계

루트 상대 경로에 보안 디렉토리 스트림·NOFOLLOW 작업을 적용해 경로 탈출·심볼릭 링크를 거부합니다. 저장소 제공자의 지원이 필요하며 오류는 서버 절대 경로를 공개하지 않습니다. 원본·데이터 루트는 겹칠 수 없고 데이터 루트 잠금으로 다중 인스턴스 충돌을 막습니다. 원본 업로드·수정·삭제 API는 없습니다.

`.folder.jpg`는 폴더 표지이며 전체 영상명 뒤 `.jpg` 파일이 자동 썸네일보다 우선합니다. 제한된 읽기·메모리 ImageIO 입력으로 JPEG 크기·픽셀을 확인합니다. 별도 이미지는 원본과 함께 외부에 남으며 영상 스트림 버전과 독립적입니다.

## 처리와 자원

분석·썸네일은 요청 시 준비합니다. 브라우저 보강 작업자 2개가 보이는/가까운 행을 우선하고 서버는 분석 2개·변환 1개·제한된 대기열과 작업 맵을 사용합니다. 지원 MP4/H.264/yuv420p/AAC는 직접 전송하며 다른 입력은 원본을 보존하고 비율을 유지해 완성 파일로 준비합니다. 실시간 HLS 변환은 아닙니다.

단일 HTTP byte range는 제한된 버퍼로 처리합니다. 서명 매개변수는 경로·버전·원본/변환 모드를 묶어 준비 스트림의 일관성을 확인하며 사용자 인증은 아닙니다. 재시작 시 키가 바뀝니다. 원본 버전에는 경로·크기·수정 시각·파일 식별자가 들어가므로 모든 입력이 같은 특수 덮어쓰기는 생성 캐시 정리가 필요할 수 있습니다.

진행 중 출력도 캐시 예산에 포함하고 사용 중이 아닌 오래된 파일을 정리하며 시작 시 알려진 미완료 작업을 정리합니다. 프로세스 수·대기열·로그·처리 시간·여유 공간·동시 전송을 제한합니다. JVM heap은 전체 컨테이너 메모리가 아니며 FFmpeg·브라우저 디코더·GPU는 별개입니다. 실제 NAS 지연·복잡한 코덱·디스크 부족·동시성은 환경별 시험 대상입니다.

## 화면과 재생

패키지 허용 목록에서 테마를 고릅니다. 문구·스타일·원본 SVG만 테마에 두고 공통 탐색·캐시·재생 로직은 복제하지 않습니다. 미리 보기는 등록 ID만 허용하고 서버 설정을 바꾸지 않습니다. 폴더 표시 문구는 경로와 독립된 일반 텍스트이며 문서 번역은 UI 현지화를 뜻하지 않습니다.

브라우저 대기열은 출처·원본 루트별 localStorage 최대 200개이며 저장 불가 시 메모리로 대체합니다. 전체 재생 스냅샷을 자연 종료로 진행하고 마지막에 닫습니다. 닫기는 미완료 작업을 무효화합니다. 원본 비율·표준 컨트롤을 유지하며 가용 뷰포트 안에 팝업을 배치합니다.

앱 HTML은 `no-store`, 실제 콘텐츠 해시와 일치하는 패키지 자원은 1년 immutable 캐시를 사용합니다. 다른 자원은 ETag·`no-cache`로 재검증하고 아카이브 시각은 변경 판단에 사용하지 않습니다. 텍스트·JSON·SVG를 압축하고 영상·JPEG는 제외합니다. 검색 대상은 `/about` 소개이며 목록·미디어는 noindex입니다. [캐시·검색 정책](configuration.md#캐시-정책)을 참고하세요. CSP는 같은 출처 자원으로 제한하며 공통 포커스·움직임 축소 규칙을 유지합니다.

## HTTP 표면

| 엔드포인트 | 목적 |
|---|---|
| `GET /api/health` | 애플리케이션 응답 상태. 전체 저장소 검사는 아님 |
| `GET /api/config` | 원본 식별자·목록 제한·테마·표시 문구 |
| `GET /api/browse?path=...&cursor=...` | 바로 아래 연속 페이지 |
| `GET /api/media/folder-cover?path=...` | 해당 폴더의 검증된 JPEG |
| `GET /api/media/info?path=...&play=true` | 분석과 선택적 재생 준비 |
| `GET /api/media/thumbnail?path=...&v=...` | 버전별 선택/자동 썸네일 |
| `GET`/`HEAD /api/media/stream?path=...&v=...&token=...` | 준비 영상·단일 부분 범위 전송 |

분석 응답의 버전·토큰을 사용하세요. 변경/누락 파일·만료 커서·처리 한도·저장소 오류는 구분해 응답합니다. 현재 접근 모델은 로그인 없는 읽기 전용이며 인증/TLS는 배포에서 구성합니다. [설정](configuration.md), [보안](../../SECURITY.md), [검증](verification.md)을 참고하세요.

## 길이순 조회

페이지 전체에서 정확히 정렬하려면 현재 폴더의 바로 아래 영상 길이를 모두 알아야 합니다. 백그라운드 작업자 2개·대기열 2개가 사용자가 연 폴더의 짧은 조회 스냅샷을 준비합니다. 페이지 읽기 작업자 2개·대기열 4개·8초 API 시간 제한으로 파일 호출을 HTTP 스레드와 분리합니다. 디렉토리 열기도 백그라운드 준비 작업에서 수행합니다. 큰 폴더가 끝날 때까지 HTTP 요청을 붙잡지 않고 준비 진행을 반환합니다. 시작 시 검색·재귀 색인·파일 감시·DB는 없습니다. 각 결과에 파일명 기반 추천과 검증한 선택적 JSON 주제를 포함합니다.

한 정렬 묶음은 최대 128개이며 외부 데이터 루트 `work/`에 임시 파일로 기록하고 한 번에 최대 16개를 병합합니다. 조회 하나는 초기 묶음 최대 4096개·직렬화 항목당 32 KiB·병합 중간본을 포함한 임시 파일 64 MiB로 제한합니다. 모든 크기의 폴더가 들어간다는 뜻은 아닙니다. 예산·여유 공간 부족은 일부만 정렬한 성공 대신 준비 실패로 안내합니다. 생성 캐시 회계·여유 공간 검사를 공유하며 전체 FFmpeg 계열 프로세스 제한은 3개입니다. 길이 분석도 기존 미디어 분석 작업자 2개를 공유하며 별도 프로세스 풀을 추가하지 않습니다.

유지하는 조회 수는 설정된 디렉토리 세션 수(기본 8개) 이내입니다. 완료/실패 조회는 일반 유휴 기간에 만료하고 사용자가 떠난 준비는 유휴 15초 후 정리 대상이 됩니다. 정리 주기는 15초이며 진행 중 OS/NAS 호출이 즉시 취소되는 것은 아닙니다. 종료 시 임시 파일을 지우고 시작 시 알려진 미완료 정렬 파일도 정리합니다. 데이터 루트 잠금은 유지합니다.

길이는 원본 버전별 LRU 최대 2000개로 재사용합니다. 파일 식별자·크기·수정 시각이 바뀌면 다시 확인하고, 길이 미상은 최대 15초만 재사용합니다. 파일 이동·주제 수정은 새 조회에 반영합니다. 완성 페이지는 스냅샷이며 재생 시 실제 원본을 재검증합니다. 정렬 커서는 공개하지 않는 조회별 비밀값으로 조회·경로·바이트 위치를 묶습니다. 유효 커서 재사용은 같은 페이지를 읽으며 잘못되거나 만료한 커서는 거부합니다. 기존 스트리밍 API의 순서별 일회성 커서는 그대로입니다.

브라우저는 설정된 페이지 크기만 받아 정확한 길이 구간과 추천/직접 지정 태그를 표시합니다. 이동 시 준비 요청을 취소합니다. 진행 확인은 요청한 정렬이 준비 중일 때만 실행하며 일반 캐시 만료로 배경 조회하지 않습니다. 큰 NAS 폴더는 바로 아래 영상 정보를 모두 읽어야 해서 오래 걸릴 수 있습니다. 자원 사용을 제한하는 설계이며 초대형 폴더의 응답 시간·기기 수용량 보증은 아닙니다.

## 시간별 랜덤 조회

`GET /api/random-playback?path=...&minutes=10`은 범위별 비동기 준비 작업을 시작합니다. 10·20·30·40·50만 허용하며 반환된 `query`를 같은 경로·시간으로 조회합니다. ID는 경로와 시간에 결합됩니다. 준비 응답은 진행률, 완료 응답은 제한된 선택 목록과 보수적으로 합산한 초, 실패 응답은 복구 안내를 제공합니다. `DELETE /api/random-playback?path=...&minutes=...&query=...`은 해당 메모리 작업만 취소하며 원본 파일을 삭제하지 않습니다. 응답에는 `no-store`를 적용합니다.

명시적 요청의 하위 탐색·표본/길이 확인 한도·단기 스냅샷·영상 전체 길이 예산은 일반 현재 디렉터리 조회와 구분됩니다. [시간별 랜덤 재생](media-library.md#시간별-랜덤-재생)을 참고하세요. 준비 데몬 작업자 1개와 대기 작업 2개를 사용하며 탐색과 길이 확인을 HTTP 요청 스레드에서 수행하지 않습니다. 대기 중인 준비는 유휴 15초 후 만료하며 5초마다 검사합니다. 완료·실패 작업은 설정된 캐시 TTL의 유휴 시간 후 정리하고 전체 준비 기한도 대기·실행 중 작업을 취소합니다. OS 호출은 인터럽트 후에도 지연될 수 있지만 작업 큐와 유지 상태는 제한됩니다.
