# 아키텍처

[English](../architecture.md) · [문서 목록](../../README.ko.md#문서)

JDK 25·Spring Boot 4.1.2 애플리케이션 하나가 정적 HTML/CSS/ES 모듈·JSON API·영상 스트림을 제공합니다. Gradle은 실행 가능한 JAR 하나를 만듭니다. 외부 파일시스템이 원본 목록의 기준이며 원본·생성 데이터 루트는 분리합니다.

## 탐색과 상태

열어 본 폴더의 바로 아래만 열거합니다. DB·시작 시 전체 검색·전역 색인·하위 개수 계산·재귀 감시는 없습니다. 기본 페이지는 지원 항목 최대 48개이며 호출당 파일시스템 항목 최대 1000개를 검사합니다. 정렬된 스냅샷이 아니므로 빈 페이지에도 다음 커서가 있을 수 있습니다.

짧은 디렉토리 세션은 최대 8개이며 유휴 시 정리합니다. 커서는 경로·순서에 묶이며 재사용·만료·불일치는 오류입니다. 읽기 작업자 2개와 제한된 대기열을 사용하고 탐색 API는 8초 후 시간 초과할 수 있습니다. 멈춘 OS 파일 호출의 즉시 취소를 보증하지는 않습니다.

탭별 메모리 LRU는 응답 20개·항목 2000개·직렬화 크기 약 10 MiB로 제한합니다. TTL 기본 120초는 최초 조회 기준이며 적중으로 연장되거나 만료 시 배경 조회하지 않습니다. 새로고침은 캐시를 우회합니다. 최근 페이지 이동 기록은 20개입니다. 이동된 파일을 전체 검색하지 않습니다.

## 저장소 경계

루트 상대 경로에 보안 디렉토리 스트림·NOFOLLOW 작업을 적용해 경로 탈출·심볼릭 링크를 거부합니다. 저장소 제공자의 지원이 필요하며 오류는 서버 절대 경로를 공개하지 않습니다. 원본·데이터 루트는 겹칠 수 없고 데이터 루트 잠금으로 다중 인스턴스 충돌을 막습니다. 원본 업로드·수정·삭제 API는 없습니다.

`.folder.jpg`는 폴더 표지이며 전체 영상명 뒤 `.jpg` 파일이 자동 썸네일보다 우선합니다. 제한된 읽기·메모리 ImageIO 입력으로 JPEG 크기·픽셀을 확인합니다. 별도 이미지는 원본과 함께 외부에 남으며 영상 스트림 버전과 독립적입니다.

## 처리와 자원

분석·썸네일은 요청 시 준비합니다. 브라우저 보강 작업자 2개가 보이는/가까운 행을 우선하고 서버는 분석 2개·변환 1개·제한된 대기열과 작업 맵을 사용합니다. 지원 MP4/H.264/yuv420p/AAC는 직접 전송하며 다른 입력은 원본을 보존하고 비율을 유지해 완성 파일로 준비합니다. 실시간 HLS 변환은 아닙니다.

단일 HTTP byte range는 제한된 버퍼로 처리합니다. 서명 매개변수는 경로·버전·원본/변환 모드를 묶어 준비 스트림의 일관성을 확인하며 사용자 인증은 아닙니다. 재시작 시 키가 바뀝니다. 원본 버전에는 경로·크기·수정 시각·파일 식별자가 들어가므로 모든 입력이 같은 특수 덮어쓰기는 생성 캐시 정리가 필요할 수 있습니다.

진행 중 출력도 캐시 예산에 포함하고 사용 중이 아닌 오래된 파일을 정리하며 시작 시 알려진 미완료 작업을 정리합니다. 프로세스 수·대기열·로그·처리 시간·여유 공간·동시 전송을 제한합니다. JVM heap은 전체 컨테이너 메모리가 아니며 FFmpeg·브라우저 디코더·GPU는 별개입니다. 실제 NAS 지연·복잡한 코덱·디스크 부족·동시성은 환경별 시험 대상입니다.

## 화면과 재생

패키지 허용 목록에서 테마를 고릅니다. 문구·스타일·원본 SVG만 테마에 두고 공통 탐색·캐시·재생 로직은 복제하지 않습니다. 미리 보기는 등록 ID만 허용하고 서버 설정을 바꾸지 않습니다. 폴더 표시 문구는 경로와 독립된 일반 텍스트이며 문서 번역은 UI 현지화를 뜻하지 않습니다.

브라우저 대기열은 출처·원본 루트별 localStorage 최대 200개이며 저장 불가 시 메모리로 대체합니다. 전체 재생 스냅샷을 자연 종료로 진행하고 마지막에 닫습니다. 닫기는 미완료 작업을 무효화합니다. 원본 비율·표준 컨트롤을 유지하며 가용 뷰포트 안에 팝업을 배치합니다.

정적 UI는 아카이브 시각을 콘텐츠 버전으로 사용하지 않고 `no-store`와 참조 해시를 사용합니다. CSP는 같은 출처 자원으로 제한하며 공통 포커스·움직임 축소 규칙을 유지합니다.

## HTTP 표면

| 엔드포인트 | 목적 |
|---|---|
| `GET /api/health` | 애플리케이션 응답 상태. 전체 저장소 검사는 아님 |
| `GET /api/config` | 원본 식별자·목록 제한·테마·표시 문구 |
| `GET /api/browse?path=...&cursor=...` | 바로 아래 연속 페이지 |
| `GET /api/media/folder-cover?path=...` | 해당 폴더의 검증된 JPEG |
| `GET /api/media/info?path=...&play=true` | 분석과 선택적 재생 준비 |
| `GET /api/media/thumbnail?path=...&v=...` | 버전별 선택/자동 썸네일 |
| `GET`/`HEAD /api/media/stream?path=...&v=...&token=...` | 준비 영상·단일 부분 범위 전송 |

분석 응답의 버전·토큰을 사용하세요. 변경/누락 파일·만료 커서·처리 한도·저장소 오류는 구분해 응답합니다. 현재 접근 모델은 로그인 없는 읽기 전용이며 인증/TLS는 배포에서 구성합니다. [설정](configuration.md), [보안](../../SECURITY.md), [검증](verification.md)을 참고하세요.
