# 문제 해결

[English](../troubleshooting.md) · [문서 목록](../../README.ko.md#문서)

## 목록이 비어 있음

새 clone에는 `movie/.gitkeep`만 있습니다. 원본 루트·현재 폴더·지원 확장자를 확인하세요. 바로 아래만 표시하며 변경 후 캐시가 남으면 새로고침합니다. 저장소 실패를 정상 빈 목록으로 간주해서는 안 됩니다.

## 컨테이너 쓰기 실패·루트 없음

마운트 경로를 먼저 만들고 컨테이너 사용자의 원본 읽기·데이터 쓰기 권한과 Docker Desktop 경로 공유를 확인하세요. 컨테이너 안에서는 호스트 경로 대신 `/media`·`/data`를 사용합니다. 루트끼리 겹치지 않게 하세요.

## 데이터 루트 사용 중

다른 인스턴스를 정지하거나 포트·데이터 루트를 바꾸세요. 두 활성 프로세스를 공유시키려고 잠금 파일을 지우지 마세요.

## 보안 디렉토리 작업 미지원

실제 마운트가 Java 보안 디렉토리 스트림을 지원해야 합니다. Linux/macOS 서버 또는 Linux 컨테이너와 적절한 저장소를 사용하세요. Windows 빌드 파일만으로 네이티브 저장소 호환성을 보증하지 않습니다. [시작하기](getting-started.md)를 참고하세요.

## 표지·썸네일 누락

[미디어 안내](media-library.md)의 `.folder.jpg`·`video.mp4.jpg` 이름, JPEG 인코딩·크기·픽셀·읽기 권한·심볼릭 링크 여부를 확인하고 새로고침하세요. 영상별 이미지가 유효하지 않으면 분석 성공 시 자동 썸네일로 대체합니다.

## 재생 대기·실패

FFmpeg/ffprobe 설치·파일 손상·코덱·여유 공간·캐시 예산을 확인하세요. 변환은 한 번에 하나씩 완료한 뒤 재생합니다. 표시되는 확장자가 코덱 보증은 아닙니다. 원인 해결 후 다시 시도하세요. 자동 재생 거절은 사용자 조작이 필요하며 파일 손상을 뜻하지 않습니다.

## 이동한 파일·대기열 경로 불일치

목록을 새로고침하고 새 경로로 대기열에 다시 추가하세요. 전체 저장소에서 새 위치를 찾지 않습니다. 만료 커서는 목록을 다시 시작합니다. 주소·포트·브라우저·원본 식별자가 바뀌면 대기열 저장 범위도 달라집니다.

## 테마·표시 문구로 시작 실패

[테마 목록](themes.md)의 정확한 ID와 [설정](configuration.md)의 JSON·범위를 확인하세요. 환경이나 파일만 바꿔도 기존 컨테이너에 적용되지는 않으므로 다시 생성합니다.

## 빌드 다운로드 실패

JDK 25와 저장소의 Wrapper를 사용하고 HTTPS 배포 서버·저장소에 대한 네트워크·프록시·CA 설정을 확인하세요. 인증서·체크섬 검사를 끄지 마세요. `./gradlew clean build` 후 [개발 검사](development.md)를 실행합니다.

## 앱 설치·연결 끊김 화면

[설정 안내](configuration.md#앱으로-설치-pwa)의 브라우저/기기 설치 절차를 사용하세요. 신뢰 HTTPS 또는 지원 localhost가 필요하며 공개 메타데이터 주소는 TLS를 켜지 않습니다. 연결 끊김 화면은 서버에 도달하지 못했다는 뜻이며 오프라인 목록이 있다는 뜻이 아닙니다. 재연결 후 다시 시도하세요. 설치 문제를 해결하려고 비공개 API·미디어를 캐싱하거나 인증서 경고를 우회하지 않습니다.

## 버그 제보

커밋·Java/Gradle 또는 이미지 버전·OS·마운트 종류·브라우저·안전한 재현과 정리한 로그를 포함하세요. 상태 API는 NAS 전체 검사 결과가 아닙니다. 개인 영상·토큰·개인 경로는 공개하지 마세요. [제보 양식](https://github.com/JunSungKang/movie-sites/issues/new/choose) 또는 [보안 정책](../../SECURITY.md)을 따릅니다.
