# 유지관리 절차

[English](../maintainers.md) · [문서 목록](../../README.ko.md#문서)

기여자는 [CONTRIBUTING](../../CONTRIBUTING.md)의 일반적인 fork·브랜치·검사·PR 절차를 사용합니다. 유지관리자 인증정보와 개인 도구는 기여자 준비 사항이 아닙니다.

## 현재 저장소 정책

`.github/codex-governance.json`은 현재 PR 작성자·담당자 계정을 제한합니다. 사람 계정이 커밋·push·통합 PR·merge를 수행하고 GitHub App이 정확한 현재 head를 formal review합니다. 필수 검사는 `quality`·`app-review`이며 push마다 새 승인이 필요합니다. APPROVED만 통과합니다.

이 계정 제약은 프로젝트의 현재 예외이며 일부 외부 fork PR의 직접 통합을 막습니다. 유지관리자는 원본 PR을 연결하고 기여자 표시를 보존한 통합 PR로 수용할 수 있습니다. 직접 통합 범위를 넓히려면 정책·도구 변경을 별도로 검토해야 합니다. 보호를 약화하거나 App 인증정보를 공개해 우회하지 않습니다.

보호·기본 브랜치는 검토 head와 분리하고 검증한 SHA만 병합합니다. 병합한 정확한 head의 원격·로컬·추적 참조를 제거하며 무관한 기여자 브랜치는 삭제하지 않습니다. 일상 코드·문서 변경에 승인 정책 변경을 섞지 않습니다.

## 릴리스 점검

1. 현재 head 전체를 검토하고 [개발 검사](development.md)와 JAR/데이터 분리를 확인합니다.
2. 실제 변경으로 [변경 기록](../../CHANGELOG.md)을 갱신하고 소스·배포 버전을 맞춥니다.
3. 별도 포트·데이터 루트 후보에서 설정·정적 파일·목록·부분 범위·대상 브라우저 재생을 확인합니다.
4. [테스트 안내](verification.md)에 따라 커밋별 결과·한계는 PR/릴리스에 요약하고 상세 운영 증적은 비공개로 보관합니다. 실행하지 않은 검사를 통과로 표시하지 않습니다.
5. 필수 검토·검사 후 병합합니다. 실제 검증된 산출물이 생겼을 때만 릴리스·레지스트리를 게시하고 존재하지 않는 다운로드 명령을 안내하지 않습니다.
6. 기존 외부 마운트·설정을 유지해 컨테이너를 교체하고 복구 이미지·설정을 보존한 뒤 확인합니다. 같은 데이터 루트에 두 인스턴스를 실행하지 않습니다.

현재 Dockerfile은 소스 빌드 방식이며 별도 레지스트리·릴리스 게시 파이프라인은 이 문서로 생기지 않습니다. 민감 신고 채널·운영 인증정보는 별도 구성이 필요합니다.

## 문서와 이력

영어가 기준이며 루트 README 하나를 문서 목차로 사용합니다. 상세 설정은 설정 안내에 두고 한국어를 같은 PR에서 갱신합니다. 전체 안내를 중복 복사하지 않습니다.

공개 문서는 설치·설정·인터페이스·재현 가능한 검사·지원 경계를 설명합니다. 작업 계획·승인 대화·호스트별 이관 실행기·스크린샷·미디어 식별 정보·운영/복구 상세 증적은 공개 안내 대신 ignored 로컬 기록으로 보관합니다. 현재 트리에서 내부 문서를 제거해도 기존 Git 이력은 지워지지 않으며 이력 재작성은 별도 작업입니다. 범용 데이터 소유권·업데이트·복구 주의는 [Docker 안내](docker.md)에 유지합니다.

기본값을 바꾸면 실행 설정·공개 환경/Compose 예시·영어/한국어 안내와 검사를 함께 갱신합니다. 표준 예시는 `compose.yaml`, 서비스 `moviesites`, 루프백 8080과 설정 가능한 비루트 UID/GID를 사용합니다. 문서 예시에 맞추려고 기존 운영 서비스를 자동으로 개명·교체하지 마세요. UI 언어·테마·주제 프로필은 별도 설정이며 테마 선택이 특정 대상 추천이나 다른 언어를 켠다고 안내하지 않습니다.
