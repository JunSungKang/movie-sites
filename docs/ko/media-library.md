# 미디어 라이브러리

[English](../media-library.md) · [문서 목록](../../README.ko.md#문서)

## 폴더와 제목

파일시스템이 실제 목록의 기준입니다. 연 폴더의 바로 아래 항목만 조회하고 하위 폴더를 열면 그 위치를 조회합니다. 현재 폴더의 모든 바로 아래 영상을 실제 길이 오름차순으로 정렬해 연속 페이지로 보여줍니다. 폴더를 먼저 표시하며 하위 전체 검색·전역 검색·하위 전체 개수 계산은 하지 않습니다. 확장자를 제외한 파일명이 제목입니다.

```text
videos/
├── Travel/
│   ├── .folder.jpg
│   ├── A day by the sea.mp4
│   └── A day by the sea.mp4.jpg
└── Tutorials/
    └── Introduction.mp4
```

한글 등 비ASCII 이름을 사용할 수 있습니다. 상대 경로는 원본 루트 안으로 제한하며 심볼릭 링크를 따르지 않습니다. 홈·목적지가 표시된 복귀 버튼으로 이동합니다. 파일 추가·삭제·이동 후 목록을 새로고침하세요. 이동된 파일의 새 위치를 전체 검색하지 않습니다.

## 이미지

폴더 표지는 해당 폴더의 `.folder.jpg`입니다. 하위 폴더를 검색하지 않으며 없으면 기본 그림을 사용합니다. 영상 썸네일은 `Introduction.mp4.jpg`처럼 확장자를 포함한 전체 파일명 뒤에 `.jpg`를 붙입니다. 없거나 유효하지 않으면 처리에 성공한 자동 썸네일을 사용합니다.

JPEG는 최대 512 KiB, 각 변 1280픽셀 이하, 전체 921600픽셀 이하여야 합니다. 폴더 960×540·영상 640×360 예시는 이 범위에 맞습니다. 테마별 잘림을 고려해 중요한 내용을 중앙에 배치하세요. 실제 플레이어는 원본 비율을 유지합니다. 별도 이미지는 원본 옆의 외부 저장소에 남으며 영상 스트림 버전과 독립된 이미지 버전을 사용합니다. 제공 권한이 있는 이미지를 사용하세요.

## 형식과 재생

MP4·MOV·MKV·WebM·AVI 등이 후보 확장자입니다. 전체 목록은 [DirectoryBrowser.java](../../src/main/java/io/moviesites/DirectoryBrowser.java)에 있습니다. 확장자가 표시된다고 모든 컨테이너·코덱 조합이 재생되는 것은 아닙니다.

지원 스트림 조건에 맞는 MP4/H.264/yuv420p/AAC는 원본을 사용합니다. 다른 지원 입력은 완성된 H.264/AAC 재생 파일로 재포장 또는 변환한 뒤 전송합니다. 원본을 보존하고 비율을 유지하며 1920×1080 안으로 제한합니다. HDR→SDR 처리는 설치된 FFmpeg 필터에 따라 다릅니다. 손상·암호화·미지원 입력에는 복구 가능한 오류를 표시합니다.

표준 HTML 영상 컨트롤을 사용합니다. 디코더·자동 재생·전체 화면은 기기와 브라우저에 따라 달라집니다. [검증 범위](verification.md)를 확인하세요.

## 재생 대기열

현재 브라우저에 대기열 하나를 보관합니다. 영상 하나 또는 현재 표시 페이지를 추가하고 순서 변경·삭제·비우기를 할 수 있습니다. 같은 경로는 중복 저장하지 않으며 최대 200개입니다. `localStorage`는 현재 출처와 원본 루트 식별자 기준입니다. 계정별 서버 재생목록이 아니며 다른 기기·서비스 주소와 공유하지 않습니다.

저장이 차단되거나 가득 차면 안내와 함께 현재 탭의 메모리 대기열로 계속 사용할 수 있습니다. 전체 재생은 첫 항목부터 스냅샷을 사용하며 도중 수정은 다음 전체 재생에 적용합니다. 자연 종료 시 다음으로 넘어가고 마지막 종료 후 팝업을 닫으며 선택 화면·저장 대기열은 유지합니다. 수동 닫기는 진행 중 재생 준비를 취소합니다. 파일 없음·자동 재생 거부는 복구 조작을 제공합니다.

## 캐시와 대용량 저장소

목록 캐시는 조회 시점 기준으로 만료되고 필요할 때 다시 조회합니다. 주기적 배경 조회는 없습니다. 응답 수·항목 수·직렬화 크기에 제한을 두며 긴 목록은 연속 페이지로 읽습니다. 파일 변경으로 목록·커서가 오래되면 새로고침해서 시작하세요. NAS·OS 파일 호출 지연과 처리 한계는 [아키텍처](architecture.md)에 설명합니다.

## 길이 정렬과 주제 태그

화면은 `GET /api/browse?sort=duration&path=...`를 사용합니다. 새 폴더 조회는 먼저 `state: preparing`, 조회 식별자·진행 상태를 반환할 수 있습니다. 같은 식별자로 준비 완료까지 확인한 뒤 서명된 다음 커서를 사용합니다. `sort=duration`이 없는 기존 API는 호환성을 위해 파일시스템 순서의 스트리밍 목록을 유지합니다. 화면은 준비 과정을 안내하고 완성된 페이지만 기존 60~180초 캐시에 저장합니다. 서버도 준비/완성 스냅샷을 고정 만료 시각까지 재사용합니다. 재사용을 우회하려면 최초 요청에만 `refresh=true`를 넣고 준비 확인 요청에는 반복하지 않습니다. 화면의 새로고침 버튼이 이 동작을 수행합니다. 파일 감시는 없으며 이동·메타데이터 변경 후 새로고침합니다.

구간은 반올림하지 않은 실제 초 기준으로 **5분 미만 / 5분 이상·10분 미만 / 10분 이상·20분 미만 / 20분 이상**입니다. 정확히 5·10·20분이면 다음 구간에 들어갑니다. 읽을 수 없거나 0 이하·유효하지 않은 길이는 마지막 별도 구간으로 표시하며 0초 영상으로 정렬하지 않습니다. 페이지가 같은 구간을 이어도 해당 페이지에 구분선을 다시 표시합니다. 처리 작업이 가득 차면 명확히 실패를 안내하며 바쁜 영상을 길이 미상으로 잘못 분류하지 않습니다.

정확한 첫 페이지를 만들려면 현재 폴더 바로 아래 영상들의 길이를 먼저 확인해야 합니다. 큰 폴더·느린 NAS에서는 처음 준비 시간이 길어질 수 있습니다. 이 단계는 길이만 읽고 썸네일은 이후 보이는 항목을 중심으로 준비합니다. 다른 하위 폴더까지 탐색하지 않습니다. 초대형 폴더의 제한은 [아키텍처](architecture.md#길이순-조회)를 참고하세요.

주제 태그는 제목 아래 표시합니다. 파일명 키워드와 일치한 값은 실제 영상 내용 분석 결과와 구분해 **추천 주제**로 표시합니다. 예절·식습관·배변·놀이·사교성·안전·건강 등의 추천을 제공하며 근거 없는 제목은 주제 미지정으로 둡니다. 추천 문구는 현재 한국어 UI 기준입니다. 직접 지정하려면 영상 전체 이름 뒤 `.json`을 붙인 외부 UTF-8 파일을 사용합니다.

```text
Tutorial.mp4
Tutorial.mp4.json
```

```json
{"tags": ["예절교육", "사교성교육"]}
```

직접 지정한 `tags`가 추천보다 우선하고 빈 배열이면 해당 영상의 추천을 끕니다. 최대 8개, 각 1~40자의 제어 문자 없는 문구를 사용하며 JSON은 최대 8192바이트입니다. 중복은 제거합니다. 잘못되거나 크거나 읽을 수 없는 메타데이터는 추천으로 대체하며 심볼릭 링크는 따르지 않습니다. 문구는 일반 텍스트로 표시합니다. 표지처럼 원본 옆의 외부·Git 제외 파일로 보관합니다. 앱은 이 파일을 쓰거나 영상을 수정하지 않습니다. 호스트/저장소에서 수정한 뒤 새로고침하세요. 원본을 읽기 전용 마운트한 컨테이너에서도 읽을 수 있습니다.
